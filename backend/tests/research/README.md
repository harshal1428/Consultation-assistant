# Research clinical-vocabulary evaluation set (v1)

This directory contains a versioned, clinically motivated evaluation set for the
VoiceSurg clinical vocabulary layer. It is deliberately separate from
`backend/tests/gold/utterances.csv`.

## Purpose

- Measure recognition of **registered-but-not-simulated** concepts, not only the
  17 geometry-backed fields.
- Exercise specific clinical vocabulary: alar flare, alar base, dorsal hump,
  tip definition, columellar show, nasal length, facial angles and ratios.
- Check that ambiguity, missing measurements, unsupported combinations and
  negated/questions are handled without silent application.
- Report results per anatomical group and per clinical key.

## Versioning and leakage

- Dataset version: `v1` (the `dataset_version` column).
- This is an **evaluation-only** set. It is never used for training, prompt
  examples, few-shot material or parameter fitting.
- The evaluator and its unit test reject exact text duplicates between this set
  and the gold set. New phrases must be added in a new versioned file rather
  than editing gold.
- Rows were written from clinical vocabulary and anatomy, not generated by the
  parser under test.

## Schema

| Column | Meaning |
| --- | --- |
| `dataset_version` | Dataset version tag (`v1`). |
| `id` | Stable row id. |
| `text` | Simulated clinician utterance. |
| `group` | `nose`, `lips`, `chin`, `jawline`, `cheeks` or `face`. |
| `expected_status` | Expected parser/live-review status. |
| `expected_clinical_parameter` | Canonical key from `shared/clinical_parameters.json`, empty when no specific concept should be claimed. |
| `expected_target` | Coarse target region expected from the parser. |
| `expected_parameter` | Coarse parameter expected from the parser. |
| `expected_operation` | Direction/operation expected from the parser. |
| `expected_value` | Magnitude in the expected unit. |
| `expected_unit` | `mm`, `degrees`, `ratio`, or empty. |
| `notes` | Why the row exists. |

Blank expected fields mean "not asserted by this dataset", except that the
evaluator asserts absence for blank target/parameter fields where the row is
specifically an ambiguity case. See `backend/app/eval/research.py`.

## Run

From `backend/`:

```powershell
..\.venv\Scripts\python.exe -m app.eval.research
```

The command prints JSON metrics and writes
`backend/tests/research/research_v1_report.json` and
`backend/tests/research/research_v1_report.md`.

## Current limitations

- The set is small and is not a clinically validated corpus.
- It contains typed text only; real microphone and ASR errors are evaluated
  separately in `docs/VOICE_PIPELINE_VERIFICATION.md`.
- Ratios are canonical ratio units, not millimetres.
- Registered-only rows must return `not_simulated`; they must not be forced into
  a similar simulated field.
